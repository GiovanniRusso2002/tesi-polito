\chapter{Introduction}

\section{Industrial Context and Legacy Constraints}
In recent years, cloud computing has progressively transformed how software systems are designed, deployed, and maintained. Organizations increasingly migrate applications from traditional infrastructures to cloud-native environments to improve scalability, maintainability, automation capabilities, and operational efficiency.

However, migrating an existing platform to the cloud is not a simple technology replacement activity. Legacy systems typically evolve over multiple years through incremental additions of services, integrations, and operational procedures. As a consequence, they embed architectural dependencies, technology constraints, and operational practices that make migration non-trivial.

This thesis analyzes Outsight Cloud (OC), a platform used to manage LiDAR-related workflows and assets, including organizations, sites, simulations, documentation, and associated files. Before migration, the platform relied on a Docker Compose-based containerized architecture integrated with several external services. Core application data was managed through Airtable, while additional capabilities depended on external storage systems, documentation engines, and notification services.

\section{Problem Statement}
The engineering problem addressed in this work is the migration of Outsight Cloud from a legacy architecture to a cloud-native environment under real technical and operational constraints.

Although the initial architecture supported rapid development in earlier product stages, several limitations progressively emerged:
\begin{itemize}
    \item strong dependency on external services;
    \item lack of robust relational data modeling capabilities;
    \item operational inefficiencies caused by manual workflows;
    \item limited scalability as platform usage increased;
    \item increasing maintenance complexity;
    \item recurring infrastructure and platform costs;
    \item absence of cloud-native orchestration mechanisms.
\end{itemize}

These limitations made the architecture progressively harder to evolve while the platform continued to grow. For this reason, the company initiated a cloudification process aimed at redesigning infrastructure and migrating services to AWS.

The migration objective was not limited to infrastructure relocation. It required redefining the architectural model, selecting appropriate cloud technologies, introducing Infrastructure as Code practices, replacing legacy components, and designing a maintainable target architecture.

\section{Thesis Scope}
The thesis focuses on designing and justifying a migration strategy for a legacy platform under real technical and economic constraints. The scope includes:
\begin{itemize}
    \item defining the problem context and migration drivers;
    \item comparing candidate cloud migration options;
    \item selecting and motivating a target architecture;
    \item presenting implementation and validation foundations already supported by project evidence.
\end{itemize}

\section{Thesis Structure}
This thesis is organized as follows:

\textbf{Chapter~\ref{chap:background}} introduces the conceptual and related-work foundations on cloud-native modernization, migration patterns, and IAM evolution in legacy systems.

\textbf{Chapter~\ref{chap:baseline}} describes the case-study baseline (as-is architecture), including technical debt and cost-related migration drivers.

\textbf{Chapter~\ref{chap:methodology}} presents the migration methodology and decision framework, including candidate options and selection rationale.

\textbf{Chapter~\ref{chap:architecture}} defines the target architecture (to-be), its main components, and design trade-offs.

\textbf{Chapter~\ref{chap:implementation}} details the incremental migration implementation foundations, with focus on IaC, data migration tooling, and validation pipeline.

\textbf{Chapter~\ref{chap:evaluation}} discusses the evaluation approach and current evidence regarding migration feasibility, quality, and impact.

\textbf{Chapter~\ref{chap:conclusions}} concludes the thesis by summarizing contributions and outlining future work.
