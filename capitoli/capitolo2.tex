\chapter{Background and Related Work}
\label{chap:background}

This chapter provides the conceptual background required to frame the migration problem and positions the thesis with respect to related work.

\section{Cloud-Native Principles for Legacy Modernization}
Cloud-native modernization is not limited to container adoption. In a migration context, it also requires reproducible infrastructure, explicit service boundaries, automated validation, and operational observability. These principles are especially relevant when modern and legacy components must coexist during transition.

\subsection{Incremental Delivery and Operability}
A recurring principle in modernization literature is incremental delivery over big-bang replacement. Incremental delivery reduces migration risk, enables early feedback, and supports rollback strategies. To be effective, it requires infrastructure automation, environment consistency, and testable interfaces between old and new components.

\subsection{Infrastructure as Code}
Infrastructure as Code (IaC) is a key enabler for modernization because it turns deployment topology, security controls, and environment configuration into versioned artifacts. This supports traceability, reviewability, and reproducibility across development and production environments.

\section{Migration Strategies and Patterns}
Common migration strategies include rehosting, replatforming, refactoring, and selective rebuilding. In practice, many enterprise projects combine these strategies across subsystems. Decision criteria generally include coupling level, criticality, migration effort, and risk exposure.

\subsection{Coexistence as a First-Class Requirement}
For systems that cannot tolerate interruption, coexistence between legacy and target components becomes a design requirement. This introduces additional complexity: contract compatibility, dual-path validation, and progressive switchover mechanisms.

\subsection{Decision-Driven Migration}
Related work often describes migration patterns conceptually, but less frequently provides explicit decision frameworks that combine technical and economic rationale. This gap is relevant for industrial contexts where architecture choices must be justified beyond purely technical preference.

\section{IAM Modernization in Legacy Systems}
Identity and Access Management (IAM) modernization is a recurrent challenge in legacy platforms. Token-based approaches and standards such as OAuth 2.0 and OpenID Connect (OIDC) provide stronger interoperability and security controls than ad-hoc authentication schemes.

\subsection{From Application-Coupled Identity to Standard Protocols}
Legacy systems frequently embed identity assumptions in application code and persistence layers. Migrating to standards-based IAM requires decoupling these assumptions, redefining authorization boundaries, and validating compatibility with existing clients and workflows.

\subsection{Open-Source and Managed IAM Trade-offs}
The choice between open-source IAM solutions and managed identity platforms affects control, integration flexibility, and operating cost. For migration projects, this decision also impacts how quickly existing services can adopt new identity flows.

\section{Limitations in Existing Approaches}
The literature provides strong foundations on migration patterns and IAM technologies, but industrial guidance is often fragmented across separate dimensions.

\subsection{Fragmented Treatment of Technical and Economic Criteria}
Technical architecture decisions are frequently discussed without detailed economic framing. However, recurring infrastructure costs, operational burden, and dependency reduction are often decisive in enterprise migration roadmaps.

\subsection{Limited Evidence on Incremental Validation}
Many case studies report final architectures but provide limited detail on intermediate validation mechanisms, such as dual-backend tests, migration data checks, and environment-separated verification workflows.

\section{Positioning of This Thesis}
This thesis addresses the above limitations through a decision-oriented migration case study. The contribution is not a generic technology survey, but an end-to-end reasoning process from baseline constraints to architecture selection, incremental implementation, and migration-focused validation.
