\chapter{Introduction}

\section{Industrial Context and Legacy Constraints}
Many software-intensive companies operate platforms that are already cloud-hosted but not truly cloud-native in design, deployment workflow, and operational governance. In these contexts, modernization is not a greenfield exercise: it requires preserving existing behavior while progressively reducing technical debt.

This thesis focuses on Outsight Cloud, a platform used to manage LiDAR-related assets and simulations. The initial system combined a Vue frontend and a Node.js/Express backend, with a data model strongly coupled to Airtable, Redis-based sessions, containerized deployment, and reverse-proxy routing. Although functional, this setup exposed structural constraints in scalability, long-term maintainability, and cost control.

\section{Problem Statement}
The core problem addressed in this work is the migration of a legacy platform toward a cloud-native architecture under real operational constraints. The migration had to satisfy the following conditions:
\begin{itemize}
    \item \textbf{Continuity:} avoid disruptive replacement and preserve business-critical flows during transition.
    \item \textbf{Security modernization:} prepare the platform for standards-based identity and access management instead of legacy authentication assumptions.
    \item \textbf{Data evolution:} progressively decouple application logic from Airtable-centric persistence.
    \item \textbf{Operational robustness:} improve reproducibility through Infrastructure as Code, environment separation, and automated validation.
    \item \textbf{Economic sustainability:} justify architectural choices also in terms of recurring cost and operational effort.
\end{itemize}

\section{Thesis Scope}
The thesis focuses on designing and justifying a migration strategy for a legacy platform under real technical and economic constraints. The scope includes:
\begin{itemize}
    \item defining the problem context and migration drivers;
    \item comparing candidate cloud migration options;
    \item selecting and motivating a target architecture;
    \item presenting implementation and validation foundations already supported by project evidence.
\end{itemize}

\section{Thesis Structure}
This thesis is organized as follows:

\textbf{Chapter~\ref{chap:background}} introduces the conceptual and related-work foundations on cloud-native modernization, migration patterns, and IAM evolution in legacy systems.

\textbf{Chapter~\ref{chap:baseline}} describes the case-study baseline (as-is architecture), including technical debt and cost-related migration drivers.

\textbf{Chapter~\ref{chap:methodology}} presents the migration methodology and decision framework, including candidate options and selection rationale.

\textbf{Chapter~\ref{chap:architecture}} defines the target architecture (to-be), its main components, and design trade-offs.

\textbf{Chapter~\ref{chap:implementation}} details the incremental migration implementation foundations, with focus on IaC, data migration tooling, and validation pipeline.

\textbf{Chapter~\ref{chap:evaluation}} discusses the evaluation approach and current evidence regarding migration feasibility, quality, and impact.

\textbf{Chapter~\ref{chap:conclusions}} concludes the thesis by summarizing contributions and outlining future work.
