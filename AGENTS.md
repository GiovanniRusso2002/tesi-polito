# Thesis Writing Directive (Outsight Cloud Migration)

This repository follows a strict thesis-writing approach.

## Core Objective
- The thesis must present the **solution to an engineering problem**.
- It must **not** be written as a diary of a six-month internship.
- The central problem is the migration of company services from a legacy setup to a cloud-native architecture.

## Suggested Title Style
- Use a problem-solution and case-study framing, for example:
  - *Migration from a Legacy Platform to Cloud: The Case of Outsight Cloud*

## Required Narrative Perspective
- Write the thesis as a **design and decision process**.
- Emphasize:
  - problem definition,
  - alternatives considered,
  - technical trade-offs,
  - economic/business trade-offs,
  - rationale for the selected solution.
- De-emphasize implementation chronology if it does not support the problem-solving argument.

## What Must Be Included
- A predefined thesis index with all chapter and subsection titles.
- A section where multiple cloud solution options are compared.
- Explicit explanation of why one solution is selected over others, including:
  - technical reasons,
  - economic reasons relevant to the company context.
- Strong focus on solution design choices made a priori.

## What Must Be Avoided
- Pure internship storytelling.
- Company-internal activities that do not contribute to problem resolution.
- Invented technical claims not supported by available material.

## Source Material Policy
Use these folders/files as primary guidance:
- `guida_cursor/report_mensili /`:
  - source for real technical work and migration evidence;
  - include only content useful to the thesis problem.
- `guida_cursor/guida.md` and `guida_cursor/OutlineTesi.txt`:
  - source for thesis structure and writing style.
- `guida_cursor/altre_tesi/`:
  - reference examples for thesis development style from past years.

## Writing Execution Rule
- Start writing only chapters/sections for which there is already sufficient material.
- Do not invent missing content.
- Update existing thesis content when it is not coherent with the real migration work and this directive.

## Priority Checklist for Any New Agent
1. Verify chapter structure coherence with the problem-solving objective.
2. Ensure each chapter answers:
   - what problem is addressed,
   - which alternatives were considered,
   - why this choice was made (technical + economic).
3. Keep language academic and evidence-based.
4. Prefer design rationale over implementation detail when scope is limited.
